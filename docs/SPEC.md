# たまにPDF — 仕様書 (v0.8.1)

> たまに使うPDFツール

## 1. コンセプト

仕事やプライベートで **たまにPDFを操作したいだけ** の人のための、ブラウザ完結型ツール。
「インストール不要」「アカウント不要」「アップロード不要」の3点を守る。

- 対象ユーザー: PDF専用ソフトを常用しない一般ユーザー
- 対象デバイス: スマートフォン / タブレット / PC (モダンブラウザ)
- 配信: GitHub Pages (静的ホスティング)

## 2. 最重要方針: PDFはブラウザから出さない

本ツールの根幹は **ユーザーのPDFが絶対にネットワークへ出ないこと**。
これは「そういう運用をしている」ではなく、**技術的に外部送信の経路が存在しない**状態として担保する。

| 担保方法 | 内容 |
| --- | --- |
| サーバ処理なし | バックエンドを持たない。全処理は `pdf.js` / `pdf-lib` によるクライアント処理 |
| CSP `connect-src 'self'` | 外部への `fetch` / `XHR` / `WebSocket` をブラウザレベルで禁止 |
| 依存アセットの自己ホスト | フォント・アイコン・CMap・wasm を含め CDN を一切使わない (外部ドメインへの接続が0件) |
| 解析ツールなし | アクセス解析・エラー収集・広告タグを入れない |
| 保存先はローカルのみ | 設定とテンプレートは `localStorage`。PDFそのものは永続化しない。自動位置合わせ (既定オフ) をオンにしたときだけ、96px幅の白黒簡易画像がテンプレートに加わる (3.3.1参照) |

CSP (本番ビルド時に `index.html` へ自動挿入):

```
default-src 'self'; base-uri 'self'; object-src 'none'; frame-src 'none';
frame-ancestors 'none'; form-action 'none';
script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline';
img-src 'self' blob: data:; font-src 'self'; media-src 'self' blob:;
connect-src 'self' blob: data:; worker-src 'self' blob:; manifest-src 'self';
upgrade-insecure-requests
```

- `wasm-unsafe-eval` は pdf.js の画像デコーダ (JBIG2 / OpenJPEG / QCMS) のために必要。
- pdf.js の JavaScript 実行機能 (`enableScripting`) は無効のまま。`isEvalSupported: false` も指定する。
- GitHub Pages は HTTP ヘッダを設定できないため `<meta http-equiv>` で適用する
  (`frame-ancestors` は meta では無効なので、埋め込み防止は別途 JS でも確認する)。

## 3. 機能一覧

### 3.1 ページ整理 (`#/organize`)

1つ以上のPDFを読み込み、ページ単位で編集して1つのPDFとして書き出す。

- ページの **並べ替え** (専用のつまみをドラッグ / 前後へ1つ移動ボタン)
  - つまみだけを掴める形にしているのは、カード全体をドラッグ対象にすると
    `touch-action: none` が必要になり、タッチでの一覧スクロールができなくなるため
- ページの **回転** (90°単位、ページごと / 全体)
- ページの **削除** / **複製** / **選択したページだけを残す**
  - 数十ページから数ページを抜き出すとき、いらないページを1枚ずつ消すのは現実的でないため
  - 履歴に積むので「元に戻す」で戻せる。1ページも残らない指定は受け付けない
- サムネイルの大きさを一覧のツールバーから変更 (小 120px / 中 168px / 大 232px / 特大 340px)
  - 中身を確かめたいだけのために設定画面へ往復させない。変えた値は設定として残る
  - スマホは既定で2列。「大」以上を選んだときだけ1列に落とす
    (2列のままでは、指定を大きくしても実際には大きくならないため)
- **ページの全画面表示** — サムネイルを押すと1ページだけを大きく出す
  - 一覧を大きくする方法では、スマホでカードの枠 (番号・つまみ・チェック・操作ボタン) が
    場所を取り、中身を読める大きさにできなかった
  - ページは 1600px 幅で描いておき、拡大縮小は描き直さずに transform で行う
    (拡大のたびに描き直すと、指を動かしているあいだちらつく)
  - **枠に収まる大きさは画面側で計算して渡す**。CSS の `max-height: 100%` 任せにすると、
    grid の入れ子の都合 (`min-height: auto`) で効かず、紙の下が切れて確かめられなくなる
  - 動かせる範囲も、枠ではなく実際の紙の大きさから決める
  - ピンチ / ダブルタップ / ボタンで 100〜400%。そのまま回転・削除・選択もできる
  - ページ送りは左右に浮かせる。下に並べると小さい画面で折り返すため
- **追加するページの選択** — すでにページがあるところへPDFを足すとき、中身を見て選べる
  - 最初の読み込みと、1ページのファイル (画像など) は確認しない
  - 設定 `addPagesMode` で「すべて追加する」にも切り替えられる (既定は選ぶ)
  - 複数ファイルを選んだときは、ファイルごとに順番に確認する。
    選択状態はファイルごとに作り直す (前のファイルの選択が残ると、件数と結果が食い違う)
  - 読み込みはファイル単位で確定する。途中で読めないファイルがあっても、
    先に読めたぶんは確認待ちに残す
- ページの **追加**
  - 別のPDFを読み込んで末尾に追加
  - 画像 (JPEG / PNG) を1ページとして追加
  - 空白ページを追加 (直前ページと同じサイズ、または A4)
- 元に戻す / やり直し (Undo / Redo)
- **一覧の間引き描画** — ページ数が60を超えると、画面に入る行だけを描く
  - 段の数と行の高さは実際に描かれたカードから測る (段組みはCSSが決めるため)
  - 描かない行は同じ高さの余白で埋め、スクロールの長さを保つ
  - 間引くのは見た目だけで、選択・回転・書き出しは全ページが対象のまま
  - 並べ替えは画面に見えている範囲どうしで行う (見えていないカードは掴めない)
- 書き出しは一覧上部のツールバーに置く。ページ数が増えるほど画面末尾は遠くなるため
- **ページ番号の付与** — 位置 (上下 × 左中右の6か所)、書き方 (`1` / `- 1 -` / `1 / 12` / `P.1`)、
  開始番号、文字の大きさ、1ページ目を飛ばすかを選べる
  - 番号はPDF標準の欧文フォント (Helvetica) で描くため、日本語は入れられない
  - ページの `/Rotate` と `/CropBox` を見て、見た目の上で正しい位置・向きになるよう座標を変換する
    (トリミング済みPDFでは、紙のサイズで置くと番号が表示範囲の外に出る)
  - 並べ替えと回転が確定したあと、最後に描く
- 破棄 (クリア) はアプリバーに一本化する。同じ操作を画面内に二重に置かない
- 出力: 元のページ内容をそのまま保持 (再ラスタライズしない)

内部モデル:

```
Source (PDFバイト列)  ──┐
                        ├─> PageRef { sourceId, sourceIndex, rotationDelta }[] ──> 出力PDF
画像/空白 → 1ページPDF ─┘
```

画像と空白ページは読み込み時点で「1ページのPDF」に変換して Source として扱うことで、
ページの扱いを1種類に統一する (拡張しやすさ優先)。

### 3.2 墨消し (`#/redact`)

**方式: 完全ラスタライズ方式**

1. 元のPDFの全ページを画像としてレンダリング (既定 150dpi)
2. 指定された矩形を黒 or 白で塗りつぶす
3. 塗りつぶし済み画像だけで新しいPDFを再構築して出力

テキストレイヤーごと破棄するため、「黒い四角を上に置いただけで下のテキストが残る」
という典型的な墨消し事故が原理的に起こらない。ページ数・ページサイズは維持される。

トレードオフ (ヘルプにも明記):

- 出力PDFは画像PDFになる → 文字検索・テキスト選択はできなくなる
- ファイルサイズが増減する場合がある
- 元PDFのしおり・注釈・フォームは失われる

矩形の座標は **ページに対する 0〜1 の正規化座標** で保持する。
これによりページサイズが違っても同じテンプレートを適用できる。

範囲の編集:

- 作った範囲はタップで選択でき、ドラッグで移動、右下のつまみで大きさを変更できる
  (角がひとつあれば調整できるので、指で押しやすい大きさを優先してつまみは1つに絞っている)
- 表示は 100〜400% まで拡大でき、拡大時はページを描き直して精度を保つ
- 拡大・移動は **2本指の操作**で行う。ピンチで倍率、2本指のドラッグで表示位置。
  パソコンではホイールで移動、Ctrl+ホイールで拡大縮小
- 表示領域の高さは CSS の `aspect-ratio` に任せる。JSで測って高さを決めると、
  その高さでページのスクロールバーの有無が変わり、幅が変わってまた高さが変わる往復が起きる
- 描画に使う解像度は整数段階に丸め、操作が終わってから反映する。
  倍率が変わるたびに描き直すと、同じキャンバスへ二重に描いて絵が壊れる
- 描画は画面外のキャンバスへ行い、出来上がってから一度に転送する (描きかけを見せない)
- 高さには上限を設ける。画面いっぱいに伸びると、その下の操作へ届くまでスワイプが続くため。
  ただし横長の画面では、高さいっぱいに広げて横に操作パネルを並べる (下記 5. 参照)
- 表示はスクロールではなく `transform` で動かす。スクロール頼みにすると、
  拡大時に縦方向へ動かせないなどの取りこぼしが出るため
- 範囲の追加・移動・サイズ変更・削除は取り消し / やり直しの対象。
  ドラッグ中の追従は履歴に積まず、指を離した時点でひと区切りとして積む

### 3.3 墨消しテンプレート

同じ発行元・同じ書式のPDFを繰り返し墨消しするための機能。

```ts
interface RedactTemplate {
  id: string;
  name: string;
  version: 1;
  rects: TemplateRect[];
  createdAt: string;   // ISO8601
  updatedAt: string;
  anchor?: TemplateAnchor;  // 自動位置合わせの基準 (3.3.1)
}

interface TemplateRect {
  x: number; y: number; w: number; h: number;  // 0..1 正規化座標
  color: 'black' | 'white';
  scope:
    | { type: 'all' }                  // 全ページ
    | { type: 'index'; index: number } // 先頭から n ページ目 (0-based)
    | { type: 'fromEnd'; index: number } // 末尾から n ページ目 (0-based)
    | { type: 'odd' }                  // 奇数ページ
    | { type: 'even' };                // 偶数ページ
}
```

- 保存先: `localStorage` (`tamani-pdf:templates`)。書き込みに失敗したら呼び出し側へ伝える
- 読み込み時、範囲が1つでも壊れていたらそのテンプレートは読み込まない
  (「読めたつもりで、隠す範囲が減っている」のを避ける)。未知のバージョンも読み込まない
- JSONファイルとして書き出し / 読み込みが可能 (端末間の持ち運び・バックアップ)

#### 3.3.1 自動位置合わせ

同じ発行元の同じ書式でも、印刷やスキャンのしかたで中身が少しずれることがある。
ずれたまま座標で当てると隠したい文字がはみ出すため、適用前にずれを推定して範囲を動かす。

```ts
interface TemplateAnchor {
  pageIndex: number;        // 基準にしたページ (0-based)
  fingerprint: {            // そのページの縮小画像
    width: number;          // 96px 固定
    height: number;         // 用紙比から決まる (A4 なら 136)
    data: string;           // 8bitグレースケールのbase64 (A4で約17KB)
  };
}
```

手順:

1. 保存時に、そのページを 384px 幅で描いてから 96px 幅へ縮め、白黒画像として持つ
   (いきなり96pxで描くと文字がつぶれて運任せになる)
2. 適用時に、相手のPDFの同じページを同じ手順で画像にする
3. 2枚を重ね、**正規化相互相関**が最大になる平行移動と倍率を探す
   - 粗い画像 (縦横1/2) で当たりを付けてから、元の細かさで詰める
   - 探索範囲は平行移動 ±12%、倍率 0.96〜1.04
   - 最後に放物線あてはめで画素より細かい位置まで求める
4. 相関が 0.55 未満、または用紙の縦横比が3%以上違うときは補正しない
5. 補正した範囲は、推定誤差に備えて各辺 0.4% だけ広げる

設計上の割り切り:

- 傾き (回転) とページごとの個別補正は扱わない。1つのずれを文書全体に当てる
- 補正量と一致度を必ず画面に出す。自動で合ったつもりにさせない
- 96px幅では本文は読めない。ただし大きな見出しなどは判別できることがあるため、
  画面の説明では「文字は読めません」と断定せず「内容の一部が判別できる場合があります」と書く

**既定はオフ** (`templateAutoAlign: false`)。
このツールを使い始める人がまず気にするのは精度よりも「何が保存されるか」なので、
既定では座標だけを保存し、画像を持つかどうかは本人に選んでもらう。

オン / オフで次の表記を切り替える (どちらの状態でも、説明が実態と食い違わないようにする)。

| 画面 | オフのとき | オンのとき |
| --- | --- | --- |
| 設定 | 何が増えるか・どこに置かれるかを説明 | 同上 (常に表示) |
| ヘルプ (プライバシー) | 「保存するのは座標だけ」 | 「簡易画像も入る」 |
| 墨消しのテンプレート保存 | 「座標だけを保存します」+ 設定への導線 | 「簡易画像も一緒に保存します」 |
| 一括墨消し | 「座標のとおりに当てます」 | 「ファイルごとにずれを測ります」 |
| テンプレートのJSON書き出し | 「座標だけが入ります」 | 「簡易画像も入ります」 |

### 3.4 一括墨消し (`#/batch`)

テンプレートを選び、複数のPDFをまとめて処理する。

結果の管理:

- 出来上がったPDFには「どの条件で作ったか」(テンプレート・解像度・形式・画質・自動位置合わせ)
  を持たせる。条件が変わったら、その結果は捨ててやり直しを促す
  — 別のテンプレートで作ったPDFが同じZIPに混ざるのを防ぐため
- 実行中はテンプレートを変更できない
- **当たる範囲が0のPDFは実行しない** (エラーとして止める)。
  「3ページ目のみ」を1ページのPDFに当てるような場合で、
  何も隠れていないのに完了扱いになるのがいちばん危ない。
  この判定は単体の墨消し (3.2) でも同じように行う
- 一部の指定が当たらない場合は、その指定を結果に併記する
- 終了時は「完了○件 / 失敗○件 / 未処理○件」を出す

- 進捗表示 (ファイル単位 / ページ単位)
- 出力: 個別ダウンロード、または ZIP でまとめてダウンロード (`fflate`)
- 1ファイルずつ順次処理 (メモリ使用量を抑えるため並列化しない)

### 3.5 設定 (`#/settings`)

- テーマ: システム / ライト / ダーク
- 墨消し解像度 (dpi): 96 / 150 / 200 / 300
- 出力画像形式: JPEG (品質指定) / PNG
- 既定の墨消し色: 黒 / 白
- テンプレート管理 (名前変更・削除・書き出し・読み込み)
- 保存データの全削除
- バージョン情報 / GitHubリポジトリへのリンク

### 3.6 ヘルプ (`#/help`)

見出しごとに開け閉めできる (`details` / `summary`)。
説明が増えるほど、開いた瞬間に文字の壁が現れて読む気を削ぐため、
普段は見出しだけが並ぶ状態にする。

- 「ファイルの扱いについて」だけは開いた状態で出す (最初に知ってほしい内容のため)
- `details` を使うので、閉じていても端末内の検索や読み上げから辿れる
- 設定の「自動位置合わせ」も同じ形にし、行には項目名だけを置く

使い方、墨消しの仕組みと注意点、プライバシーの説明、FAQ、既知の制限。

## 4. 技術構成

| 項目 | 採用 | 理由 |
| --- | --- | --- |
| ビルド | Vite + TypeScript | 定番・高速・型安全 |
| UI | React 19 | 状態の多い画面を宣言的に書ける |
| PDF描画 | pdf.js (`pdfjs-dist`) | Mozilla製。ブラウザPDF描画の事実上の標準 |
| PDF生成/編集 | pdf-lib | 純JS。ページ操作・画像埋め込みに対応 |
| D&D | dnd-kit | タッチ操作に対応した並べ替え |
| ZIP | fflate | 小さく高速。依存なし |
| デザイン | Material Design 3 準拠のCSSトークンを自前実装 | 外部フォント/アイコンCDNを使わずM3の見た目を得るため |

アイコンはすべてインラインSVG (`src/ui/icons.tsx`)。外部リクエストを0件に保つ。

## 4.5 作業を失わないための決まりごと

このツールはPDFを端末の外へ出さない代わりに、どこにも保存していない。
そのぶん「消えたら終わり」なので、次を守る。

| 場面 | 決まりごと |
| --- | --- |
| 画面の切り替え | 作業中の画面 (整理・墨消し・一括) は消さずに隠す。読み込んだPDFと編集内容はそのまま残る |
| 隠れている画面 | アプリバーへのボタン差し込みとダイアログの表示を止める (前面の画面と混ざらないように) |
| 別のPDFへの切り替え | 消えるもの (指定した範囲) があるときは、先に確認する |
| タブを閉じる・再読み込み | 読み込んだPDFがあるあいだは `beforeunload` で引き止める |
| 端末への保存 | 失敗したら必ず伝える。「保存しました」と出したのに消えている状態を作らない |
| 取り消しの導線 | ページが無くなっても、戻せる履歴があるあいだは「戻す」を出し続ける |
| 書き出したあと | 書き出してから変えていないあいだは引き止めない (保存済みを未完了に見せない) |

ダイアログは開いた瞬間だけ焦点を移し、以降は操作に任せる。
`onClose` のような毎回作り直される関数を効果の依存に入れると、
入力のたびに焦点が飛んでしまうため。開いているあいだは Tab を内側で回し、
閉じたら開くのに使ったボタンへ戻す。

## 5. 画面構成

```
#/            ホーム (ツール選択)
#/organize    ページ整理
#/redact      墨消し
#/batch       一括墨消し
#/settings    設定
#/help        ヘルプ
```

ハッシュルーティングを使う (GitHub Pages で 404 を出さないため)。
PC は左のナビゲーションレール、スマホは下部ナビゲーションバーに切り替える。
切り替えの条件は **幅 840px 以上 かつ 高さ 600px 以上**。
レールは6項目ぶんの高さ (約470px) を必要とするため、幅だけで判定すると
横向きのスマホでレールが画面の高さを超えてしまう。

### 画面の向きによるレイアウト

墨消しは CSS グリッド (`grid-template-areas`) で2種類の配置を持つ。

| 画面 | 配置 |
| --- | --- |
| スマホ (幅760px未満 **または** 高さ600px未満) | ツールバー → プレビュー → 説明・範囲一覧 の縦積み |
| PC・タブレット (幅760px以上 **かつ** 高さ600px以上) | 左にプレビュー (高さいっぱい)、右にツールバーと各パネル |

左右に分ける配置では、見出しとフッターを畳んでプレビューを高さ基準で拡大する。

判定に高さを含めているのは、横向きのスマホ (例: 844×390) で左右に分けると
どちらの列も窮屈になり、縦積みのほうが扱いやすいため。
スマホは端末を横に倒しても縦長と同じ並びのままになる。

なお、ブラウザから画面の向き自体を固定することはできない
(`screen.orientation.lock()` は全画面表示またはインストール済みPWAでのみ有効)。
そのため「向きに関わらず同じ並びにする」形で対応している。
